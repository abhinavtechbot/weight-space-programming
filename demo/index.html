02 / WHAT'S ACTUALLY HAPPENING

From words
to weights.

The transformer is a real two-layer model. Its weights are written directly in Rust; they are not trained and an LLM does not write them at runtime.

01

Match a small vocabulary

A simple text matcher looks for an action word and “left”, “middle” / “center”, “right”, or “all bulbs”. It does not understand arbitrary language; negation and turn-off requests are unsupported.

02

Write the circuit

Each recognized position becomes an input token. Hand-written embedding, attention, ReLU and output-head weights convert the tokens into three independent outputs—one per bulb. No argmax means multiple bulbs can light.

embedding[LEFT, 0]   = 1
embedding[MIDDLE, 1] = 1
embedding[RIGHT, 2]  = 1

output[left]   → turn_on_left()
output[middle] → turn_on_middle()
output[right]  → turn_on_right()
03

Execute the tools

Each selected tool updates that side's own virtual bulb panel. The LLM gets the original text and the same three tool definitions; its actual tool calls update a separate panel.

COMPARE FAIRLY

The LLM can interpret phrasing the matcher cannot. The forward-pass time excludes text matching and process startup; the LLM time includes the network and API. A rules engine could also solve this fixed task, often more simply. Matching panels do not establish accuracy across all possible text.
