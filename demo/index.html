02 / HOW THE WEIGHTS ARE WRITTEN

Rules become numbers.

This circuit is constructed by a person as algebra in Rust. There is no training, and no LLM writes the weights at runtime. The snippets below summarize program_weights(); the gate expressions are conceptual, not literal Rust.

01 / REPRESENT THE INPUT

Give each event a channel

embedding[Search, 0] = 1
embedding[Bash,   1] = 1
embedding[Danger, 2] = 1

The query token gathers event channels through uniform causal attention. ReLU units then turn them into presence signals.

02 / BUILD THE LOGIC

Write the routing gates

Search = ReLU(search − bash)
Bash   = ReLU(bash − danger)
Oracle = ReLU(bash + danger
              − reference)

These are conceptual expressions: the real circuit includes normalization and reference channels. The output head reads the active gate.

03 / RUN THE CIRCUIT

Execute the actual model

kernel.program_weights();
route = kernel.forward(events);

Each result above comes from the actual two-layer Rust transformer, with 79,555 float parameters and no gradient updates.

03 / WHAT THIS PROVES

A useful narrow circuit, not a replacement for an LLM.

Where it helps. A fixed, bounded, frequently repeated decision can run locally without an API call. The weights and rules are inspectable, and changing inputs produces a real model output.

What it doesn’t do. This circuit cannot understand arbitrary text, invent rules, use tools, or detect danger. A conventional rules engine can solve this task more simply. The LLM is more general; this experiment measures only this narrow job.

Accuracy needs evidence. A rule match is calculated against the displayed contract. Try different combinations and repetitions; a few examples cannot establish general reliability or prove one system is universally better.
