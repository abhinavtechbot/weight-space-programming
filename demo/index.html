03 / WHAT'S ACTUALLY HAPPENING

From words
to weights.

The model is a small recurrent ReLU network. Codex wrote a Rust program that directly initializes its weights; no gradients or pretrained language model are used. It is not the earlier transformer.

01

Tokenize the text

A mechanical tokenizer lowercases and splits the text into words. It preserves order and does not decide the bulb intent. Known words are mapped to IDs; unknown words have no learned meaning.

02

Write the circuit

Written embedding weights encode a small set of position words, action words, and exclusions. A recurrent ReLU circuit updates three bulb flags and an exclusion flag as it reads each word, producing three independent outputs.

embedding["first", LEFT]   = 1
embedding["centre", MIDDLE] = 1
embedding["except", EXCLUDE] = 1

output[left]   → turn_on_left()
output[middle] → turn_on_middle()
output[right]  → turn_on_right()
03

Execute the tools

Each selected tool updates that side's own virtual bulb panel. The LLM gets the original text and the same three tool definitions; its actual tool calls update a separate panel.

COMPARE FAIRLY

The written vocabulary and grammar are limited: unfamiliar words, complex negation, and references can fail. The LLM can interpret a wider range of phrasing. The network time includes tokenization but excludes process startup; the LLM time includes the network and API. A rules engine could also solve this fixed task, often more simply. Matching panels do not establish accuracy across all possible text.
